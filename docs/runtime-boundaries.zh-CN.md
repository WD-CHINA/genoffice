# 三端运行边界与待验收事项

更新日期：2026-11-12。配合[功能与架构](runtime-workflows.zh-CN.md)、[测试与本轮证据](testing-guide.zh-CN.md)阅读。

本文中的“已实现”表示代码具有处理路径，“回归覆盖”表示有相应断言；只有本轮报告明确成功的场景才视为本轮实测。历史报告保留当时条件，不能代替当前环境或完整生产验收。

## 1. 文件、格式与输入

| 触发条件                                         | 当前处理                                                                                                                | 剩余边界 / 验证要求                                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| 文件超大、大小未知或压缩后很小                   | Viewer 预检、本地/服务端阈值、服务端上传/part/解压总量限制分开检查                                                      | 压缩包大小不能表示正文解压体积；GB 正文、GB 媒体和常规文档是不同场景                                               |
| 扩展名与真实格式不一致、损坏 ZIP、异常路径或 CRC | 识别与 ZIP gate 校验；拒绝无效输入，part 路径限定在受控范围                                                             | 不得通过降低限制或忽略校验让异常样本通过；覆盖 limits、parts、bundle 和损坏测试                                    |
| 加密文件、HTML/MHT altChunk、其他未支持内容      | 本地 DOCX 有密码提示与解密流程，PDF 有 PDF.js 密码回调；服务端 Office 解析仍需符合其输入限制，altChunk 等明确提示不支持 | 本地原文件可解密不等于服务端模型或离线包可解析；错误密码、取消及各端密码交互尚需专项业务验收，不能删除相关兼容测试 |
| capabilities 缺失或阈值无效                      | 兼容旧服务并使用有效默认值，失败探测不缓存                                                                              | capabilities 是路由依据，不是实际可用内存或吞吐证明；32/64 MiB 为默认路由阈值                                      |
| Viewer 与服务端限额不一致                        | 各入口执行自己的硬限额与部署配置                                                                                        | 当前 Viewer 本地文件预检 1 GiB、服务端默认上传 2 GiB；不能把服务端上限当成浏览器必然可打开的文件大小               |

大正文使用流式提取和持久 chunk，并不保证冷任务立即出现可读预览。本轮 1.12 GB 正文在约 52.1 秒后 ready，报告未记录更早的 `previewable` 阶段；首/中/尾 chunk、并行缓存阅读及健康探测均验证通过。命令和资源条件见[测试指南](testing-guide.zh-CN.md)，不能将此时间外推为生产承诺。

| DOCX 跨页表格各列行距不同                                 | 按各单元格行盒独立续排；短内容仅首次片段对齐和显示；续页封边保留样式         | 不把多个单元格强制切在同一高度；边框 nil/double/颜色、右边界及字符零遗漏/零重复分别检查                                                                              |

| 分节、连续分节、双栏、奇偶页、页眉页脚与字段              | 通过节上下文、实际页眉页脚高度、页码与总页数字段参与布局                     | 未完成加载时总页数可能待定；纸张、列、脚注和跨 chunk 范围必须联合验证                                                                                                |
| 业务课时计划对照飞书                                      | 图片比例、右边框、续页边框、字体上下文与普通单元格续排已有专项回归           | 历史飞书对照记录为 5 页，本轮本地仍为 5 页，未重新取得飞书基线；换页位置及预计运动负荷合并区等不宣称逐行一致。见[表格复验](docx-table-cell-flow-validation.zh-CN.md) |
| PPTX 预加载与动画同时发生                                 | 页级更新与动画状态分离，回归中检查动画中间态及完成后翻页                     | 模型 JSON 相同不能代替渲染树/像素或真实动画验收；GIF、组合变换和遮挡仍需独立覆盖                                                                                     |

## 3. 媒体与播放

| 触发条件                                    | 当前处理                                                    | 剩余边界 / 验证要求                                                                    |
| ------------------------------------------- | ----------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 扩展名为 MP4 但编码不兼容，或 moov 位于后部 | 探测实际流、profile、像素格式及容器；选择复用、重封装或转码 | 更名为 mp4/mp3 不等于转换；必须验证实际输出、时长和可播放性                            |
| 兼容视频与音频混合、同一 part 有不同角色    | 缓存身份包含源摘要与准备 profile/角色；分别选择资源映射     | 不能仅按文件名共享错误结果；缓存命中、跳过转码和强制重试是不同断言                     |
| 排队、失败、超时、取消或节点退出            | 持久作业与租约、有界进程和资源预算、客户端进度及重试        | 探测/转换完成不等于结果已发布；需验证杀进程后接管、相同 jobId、旧版本保留及 Range 读取 |
| 外链媒体、引用遗漏或资源未完整准备          | 标记外部/不完整范围；内嵌资源清单与已准备媒体共同下载       | 外链无法自动保证离线；未引用但有效的过渡音频也可能是完整包的一部分                     |
| Android 浏览器内核、自动播放或静音限制      | 复用 HTML 媒体控件与用户交互入口，提供明确错误状态          | 静音推进时间只证明解码/播放管线，不证明可听音质、扬声器输出或所有设备支持              |

业务音频对象若落在画布外或被工具条遮挡，播放探针可以通过分发组件事件单独验证解码，但这不能算真实指针/触控可达。演练以 `previewPointerReachable`、`showPointerReachable` 或 `pointerReachable` 记录并保留警告，不把组件触发结果替代用户交互验收。

本轮在 Chrome 157 的业务视频上复现了共享放映播放器的点击冲突：自定义 `toggle` 先播放，随后原生 controls 默认动作暂停，时间停在 0。`media-click-probe.json`、`media-click-stacks.json` 保留复现，`media-controls-probe.json` 验证候选防重复切换处理仍可使用进度条和原生播放按钮。共享放映层现已增加默认动作去重处理，Chrome 实际修复、原生进度条/播放按钮及业务/编码播放矩阵通过；新 APK 的逐文件触控复验也已通过，原始失败记录保留。Android 114 的旧实现本机未复现同一单击问题，补丁后兼容性经过实机验证。

转码实现选择首个有效视频流和首个音频流，并移除字幕/数据流；未承诺多音轨选择、字幕、章节或 DRM 内容保真。复用兼容文件与重新编码对这些内容的影响也不同。

## 4. 网络、会话与并发

| 触发条件                               | 当前处理                                                                                              | 剩余边界 / 验证要求                                                                                       |
| -------------------------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 弱网、签名过期、重连或缓存 URL 失效    | 有界重试、刷新描述或签名、会话恢复并从已提交 cursor 继续                                              | 不能无限重试，也不能重复提交已读 chunk；缓存新鲜与过期必须分别验证                                        |
| 异步模式不支持与普通错误混淆           | 仅在异步 POST 明确返回 404/405 时移除 Prefer 头，同步重试 `/v1/sessions`；429/鉴权/作业失败不绕过控制 | Android 本地重放直接使用 v1，同步返回会话；测试只允许明确接口的预期响应，并要求真实本地会话与内容读取成功 |
| 多个读者等待同一冷构建，其中一个取消   | 共享任务、各自等待者身份与幂等账本；最后等待者取消另行处理                                            | 串行两次请求不证明并发安全；保留 FIFO、队列溢出、最后等待者和重启接管测试                                 |
| 500 个会话、少量冷任务或缓存命中       | 将轻量会话数、解析并发、队列和缓存阅读分开限制和计量                                                  | 不从“500 会话成功”推断 500 个并发冷解析；长稳也不能代替容量压测                                           |
| 关闭、文件切换、请求或字体等待尚未完成 | AbortSignal、窗口请求取消、作用域回收；原生 generation 阻止旧结果覆盖新任务                           | 迟到回调不得恢复旧页面、重启 heartbeat 或保留离屏 DOM；前后台切换和系统杀进程仍依机型验证                 |
| 网络全断与仅后端断连                   | 离线测试关闭测试后端或移除 USB 转发，并检查外部资源请求                                               | 这能证明受测资源不依赖后端；未关闭 Wi-Fi/移动网络时应明确记录，不能称为设备全部网络物理断开               |

## 5. 存储、缓存与恢复

| 触发条件                                                     | 当前处理                                                                      | 剩余边界 / 验证要求                                                                                                                       |
| ------------------------------------------------------------ | ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| 同名文件、重复上传或参数变化                                 | 源内容寻址；产物 identity 与布局键独立版本化                                  | 文件去重不等于解析结果可复用；布局/指纹/schema 不同不能误读旧模型                                                                         |
| 多实例同时写、旧租约迟到提交或回收竞争                       | catalog、generation、读写租约与 fencing；回收再次核对身份                     | local 测试不能代替真实 MySQL 竞争；Redis 的故障或数据丢失不能改变持久 ready 事实                                                          |
| 原文件丢失、产物损坏、清单摘要变化                           | 按代际校验、撤销无效 ready、有限重建；恢复校验对源丢失拒绝就绪                | generation 损坏可重建不意味着源文件丢失也可忽略；对损坏副本注入故障，保留原始数据                                                         |
| Android 下载中断、服务忽略 Range、ETag 或 Content-Range 不符 | 校验续传身份与响应，按规则重下，最终验证全文件摘要                            | 长度相同仍可能损坏；未知长度也必须持续检查空间预算                                                                                        |
| 磁盘不足、缓存配额、并发下载与清理                           | 下载前及过程中检查；Android 保护各文件 current 及显式指定版本；失败不切换指针 | 检查后空间仍可能变化；Android 无独立读租约，仍在播放的非 current 旧包可能被回收，需重新打开。服务端活跃 generation 的租约保护是另一条路径 |
| 发布、取消或进程退出发生在 seal/current 切换期间             | staging、完整清单、版本指针及旧版本恢复；保留必要 legacy 读取兼容             | 半包、外链、不支持 schema 或错误摘要不得标记完整离线可用                                                                                  |
| 服务正常退出与强杀                                           | drain、取消、读租约、持久投影与有界退出；强杀后由恢复路径接管                 | 正常退出通过不能代替 SIGKILL；测试清理必须等待服务退出期限并固定本用例资源所有权                                                          |

Android 默认 2 GiB 配额用于单包准入及回收非 current 历史/临时数据，不保证总占用始终低于配额。多个文件的 current 和旧版 flat 包都受保护，累计可能超过配额；不能通过删除这些有效包让测试过关，仍需部署方决定跨文件保留策略与可用空间预算。

Android 本地服务绑定 `127.0.0.1`，检查当前 fileId 和资源路径，不提供与远程 Bearer 接口相同的身份模型。若集成方要求只有当前 WebView 可访问敏感文档，应另行验收本地访问隔离；本轮不据“环回地址”宣称已完成这项安全验收。

### Android 服务端目录与主题

服务端目录通过鉴权的 `GET /v1/files` 分页加载；网络、令牌失效或旧服务没有接口时明确报错，空目录单独提示。返回或销毁页面取消请求并丢弃过期响应。列表只代表当前已上传文件，名称可能回退为格式与 ID 前缀；读取不延长保留期，列出后过期/删除的文件仍可能打开失败。文件存储模式扫描元数据，不保证与 MySQL 分页相同的目录规模性能。断网时可在设置页按 ID 打开已缓存离线包，不能依赖远程目录可用。

Android 原生界面与默认预览为浅色；设置中的跟随系统/深色选择会持久保存。跟随系统在每次打开预览时解析，已打开 WebView 内的系统主题热切换未纳入本轮范围。列表的已缓存标记只说明封存记录存在，打开时仍须通过完整性校验；不能以标记替代校验成功。

## 6. 部署与验收边界

- 原文件/媒体卷、MySQL、解析指纹和备份清单必须作为一致集合恢复；Redis 不代替备份。回滚需同时检查 schema、模型和已发布 generation 的兼容关系。
- 同一 Docker VM 中复制目录、卷或使用另一数据库，验证的是独立恢复流程；没有第二台物理机器时，不宣称已完成真实异机验证。
- 容器 `cpus` 和 `mem_limit` 是配额，不代表独占 CPU 或实际物理内存。本轮 Docker VM 的实际资源、各容器限制和测试并发方式写入验收记录，不外推 8 核/16 GiB 生产容量。
- 本地弱网代理的逐响应延迟/限速，不等于共享带宽、丢包或所有站点脚本均经过同等网络条件；报告必须保留实际模拟范围。
- `promtool` 只验证告警规则及规则测试；真实通知投递、生产收件路由及线上版本发布/回滚仍需在目标部署环境验收，不能用本机规则成功代替。
- JS 堆和 Android 主进程 PSS 不等于浏览器/GPU/解码器完整内存。合成 50 页长稳不认证所有音视频持续长播或厂商低内存重建路径。
- UI、可见图像、语义、模型、资源哈希、字符覆盖、内存与时延是不同验收维度。测试精简只合并重复设施和等价分支，不用一类结果替代另一类。

## 7. 维护时的判定规则

1. 每次变更对应到需求、边界与具名测试。保留输入、故障阶段、关键断言和旧到新映射；没有替代覆盖不删除有效用例。
2. 将测试基线失败、测试设施缺陷和产品缺陷分别记录；不得删除失败断言或随意放宽阈值以制造通过。
3. 常规测试依赖缺失造成的跳过不视为成功。真实数据库、Android、长稳与故障注入分层执行，分别保存结果。
4. 测试样本和故障注入使用私有临时目录、数据库及容器；业务文件只读，不清空设备数据，不把私有文件或大体积证据加入 Git。
