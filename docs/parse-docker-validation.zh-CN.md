# Viewer / parse-server Docker 验证记录

日期：2026-11-11。范围：当前工作区实现、用户指定的本机课件目录、隔离 Docker 服务。业务文件、截图、SQL 备份均未加入 Git。

**当前结论：基础链路、容量保护和容灾验证通过；复杂文档验收存在明确未通过项，尚未达到完整生产交付标准。** 本记录取代旧文档中互相冲突的完成度百分比作为当前验收依据。

## 环境与口径

- Docker Desktop：Linux ARM64、cgroup v2，虚拟机可用内存约 7.75 GiB、10 个逻辑 CPU。没有修改用户的 Docker 全局资源配置。
- 负载容器：`cpu.max=800000 100000`（8 CPU 配额）、`memory.max=6442450944`（6 GiB）、禁用 swap。**这不是 8 核 / 16 GiB 机器验收。** CPU 配额也不等于独占八个物理核心。
- Node 22.23.4、MySQL 8.0.46、Redis 7、真实 Chromium。验证镜像单独安装 Linux 依赖，不复用 macOS 的 node_modules；它是验证环境，不是已完成依赖闭包审查的生产镜像。
- 实际业务样本为 9 份 PPTX、1 份 DOCX、1 份 PDF；另一个以 `.~` 开头的文件是 Office 临时文件，排除。最大 PPTX 181,664,509 字节。
- PPTX 共 117 页，涵盖动画、嵌入字体、图片和媒体。样本没有原生图表；业务 DOCX 有表格，没有页眉页脚和多分节。缺失场景使用仓库夹具补充，不计为业务样本验收。

## 浏览器与复杂 DOCX 未通过项

1. **业务浏览器抽样：29 页中 28 页完成加载检查。** 覆盖每份 PPT 首 / 中 / 尾页、业务 DOCX 首页、PDF 首页。最大 PPT 首页两次未出现 `currentPageImagesReady`（30 秒、60 秒），截图可见内容，但不能证明全部素材加载完成。需要核查该页资源及图片解码，不把“有画面”算作完整通过。
2. **字体替代仍存在。** 多份文件提示 Adobe 黑体、等线、微软雅黑、PingFang SC 等未包含在字体包中。嵌入字体请求没有被记录为加载失败，也不能由此认定所有字体外观准确。未擅自加入未经许可分发的系统 / 商业字体。
3. **DOCX 流式脚注编号回归。** 8 份正文语义对照中 **7 份通过、1 份失败**。`06-with-footnotes.docx` 正文第 1 个脚注在完整解析器中是 `1`，远程模型是 `*`。原因可追溯到 `createDocxBlockParser` 在传入流式 metadata 时使用空 `noteNumbers`；此项尚未修复。
4. **远程 DOCX 分节及页眉页脚缺失。** 多分节、双栏和页眉页脚夹具的正文块 / 文本 / 表格行数可以一致，但远程 document model 仅给一组 page settings，没有 sections、headers、footers；Viewer 远程路径也按一组页面设置排版。七分节 / 七个页眉页脚 part 的夹具因此不能认定版式通过。
5. **弱网抽样通过但有字体提示。** 一份小业务课件首页经本地代理增加 200 ms 延迟、每响应 128 KiB/s 下行限速后显示成功。此为逐响应限速，不模拟共享链路总带宽、丢包、断网或整个站点脚本下载。
6. **没有独立 Office 视觉基线。** 一份含动画的 23 页业务课件通过进入放映、键盘推进和退出冒烟；当前截图、模型重启一致及播放冒烟不能替代与 PowerPoint / Word 的逐页、逐帧对照。业务图表和全部动画类型仍未验收。

## 冷恢复演练

停止源服务写入，生成一致清单；用 `mysqldump` 导出指定的隔离 catalog 库，将持久化字节复制到**另一个独立数据卷**；启动第二个独立 MySQL 容器并导入 SQL，执行深度校验和启动门禁。

- 清单 74 项、48 条 catalog 概览记录，校验 **690,941,835 字节**，18 个 ready 指针。
- 独立目标校验 `ok=true`、`readyAllowed=true`，启动门禁通过。
- 目标服务重开全部 11 份业务文件：模型 / Range 一致，源解析启动数 **0**。
- 目标卷中篡改一个原文件后，深度恢复校验返回 `source_size_mismatch`、`ok=false`、`readyAllowed=false`，进程退出码 1；具体结果保留在 `restore-tampered.json`。
- **这是同一 Docker VM 的独立容器、数据卷和数据库恢复，不是真实第二台物理机或外接介质演练。** 没有验证宿主机损坏、跨架构迁移、备份调度 / 保留策略或生产值班链路。
