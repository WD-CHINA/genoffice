## 修复内容

| 问题                         | 根因                                                                          | 当前行为                                                                                                                   |
| ---------------------------- | ----------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| DOCX 脚注序号变成 `*`        | 流式解析没有传入全文引用顺序，block parser 的 noteNumbers 为空                | 元数据扫描只保留引用 / 分节标记，复用原解析器的编号规则；覆盖跨 chunk、按节重新编号和重启复用                              |
| 远程 DOCX 没有分节和页眉页脚 | 持久模型只包含最后一节的六个页面尺寸字段                                      | 模型携带逐节范围 / 几何 / 分栏、富文本页眉页脚及图片；前端逐节测量分页，显示继承、首页 / 奇偶页变体及 PAGE / NUMPAGES 字段 |
| 最大 PPT 首页图片一直未就绪  | `image11.emf` 是远程 URL，旧图片加载器只转换 EMF data URL，浏览器无法直接解码 | 远程 / Blob EMF、WMF 先经过原有矢量转换器栅格化，再进入图片解码队列；保留大小上限、2048px 栅格上限及签名刷新重试           |

实际浏览器检查还发现并修复了两个关联问题：v2 缓存打开响应没有把页眉图片的内部域名重写并签名；离屏测量使用了不同 CSS 作用域、忽略段落间距，且短双栏末页没有均衡。当前页眉图片在读取时生成当前部署的 URL，测量与展示采用相同宽度及样式，末页按段落 / keep-with-next 边界均衡分栏。

DOCX 文档上下文与 body chunks 分开持久化。服务端不会重新持有完整正文 XML；编号参考骨架不含正文文本，阅读端只保留数字布局索引及可见窗口的 body models。资源签名只处理 hfParts，不为每个会话复制大型脚注集合；持久记录不保存短期签名或部署域名。

## 验证结果

- **真实 MySQL + Redis：554 / 554，无跳过。** 新增回归覆盖跨 200-block 边界的脚注、分节范围、富文本页眉页脚、v2 热缓存图片 URL、服务重启后图片读取。
- **Viewer：106 / 106。** 覆盖连续 / 下一页分节、不同纸张宽度、分栏、末页均衡、页眉空间预留、跨单元 keep-with-next、奇数页插空及远程 EMF 的签名重试。
- **原 DOCX 引擎相关测试：100 / 100**（notes、note-props、header-footer-rich、header-footer-textbox、sections）；**共享契约：13 / 13**。类型检查、ESLint 无错误，Viewer 构建通过。
- **用户提供的 11 份实际业务文件：接口和重启复用全部通过。** 117 个 PPT 页及 1 个 DOCX chunk 重启前后哈希一致，PDF Range 字节一致；重启后源解析启动数为 0。
- **业务浏览器抽样：29 / 29 完成加载与运行检查。** 覆盖每份 PPT 的首 / 中 / 尾页、实际教案及 PDF。部分文件仍有字体替代提示。
- **DOCX 语义与布局样本：8 / 8。** 实际教案加长表格、脚注、连续分节、横纵向纸张、双栏、重复表头、七节图片页眉夹具；正文、编号和节范围与原解析器一致。浏览器遍历全部源节，检查纸张尺寸、列数、正文不溢出及页眉图片解码。
- **七节图片页眉：七节全部显示**，图片资源成功解码，正文预留使用原 HeaderFooterArea / hfReservedHeightPx 逻辑。
- **实际教案页脚：`第 X 页，共 Y 页` 字段已恢复。** 上轮清单仅匹配 footer1.xml 等编号文件名，漏记了业务文件的 footer.xml；当前按 relationships 类型识别。浏览器对 PAGE / NUMPAGES 和实际分页结果做了断言，并保留页脚截图。
- **最大课件首页：图片就绪检查通过。** 截图中的 EMF 对象图标及文字实际出现；最终验证 `currentPageImagesReady` 约 1.46 秒（早期独立验证 1.81 秒），不再是原来的空白框 / 60 秒超时；进入放映、键盘推进及退出也通过。这不是跨设备性能承诺。
- **GB 正文回归通过：** 1,119,671,617 字节正文 XML、65,536 段，约 59.26 秒生成 328 个 chunk，抽查首 / 中 / 尾单元；117 次健康探针，p95 约 38.60 ms，父子 RSS 采样峰值约 0.785 GiB。样本 / 主机条件与上轮相同，但不把两次耗时差异解释为固定加速比例。

本轮仍使用本机 Docker Desktop 的约 8 GiB VM；没有补称 16 GiB 或第二台物理机验收，也没有把这批样本等同于所有 Word / PowerPoint 文件的独立 Office 视觉验收。
