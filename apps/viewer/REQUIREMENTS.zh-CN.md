# Office Viewer 需求文档

版本：1.0 · 整理日期：2026-10-13。

本文汇总用户已确认的产品范围、开发边界和界面调整，并记录当前实现及待验收事项。原渲染源码基线为 `4863835963c99793c47b72473900c483e9fa0c2a`；本文整理时的代码提交为 `930ae6c1`。后续范围以用户最新确认和本文件更新为准。

“已实现”表示入口已接入并有相应功能验证，不等于所有复杂文件已通过与原 GenOffice 的逐页视觉对照。“待验收”表示仍需样本或基线证据。“待确认”表示用户尚未决定具体业务策略。

## 1. 产品目标

在现有仓库中提供独立的静态预览页面。打开、解析、排版和绘制都在浏览器中完成，用于 Office 文件只读预览、PPT 放映和音视频播放。

首期支持 `.pptx`、`.pdf`、`.docx`，应用位于 `apps/viewer/`，开发、启动、构建和生产运行均可独立于其他模块进行。

还原对象是原 GenOffice 的显示和播放结果。解析、字体度量、排版、内容绘制、节点结构、内容 CSS、动画和转场继续沿用原实现；用户界面的文件栏、工具栏等宿主控件可独立调整。

| 编号 | 要求                                  | 验收口径                                                                                            |

| B-02 | 一个独立 Viewer app                   | 开发入口只启动 Viewer 的 Vite；生产只托管静态目录                                                   |
| B-03 | 只读预览、播放、放映                  | 不提供编辑、保存写回、AI、批注新增、表单填写或签署入口                                              |
| B-04 | 完全沿用原项目渲染方式                | 保留原解析、排版和绘制链路，并与原程序做内容与播放对照                                              |
| B-05 | 不影响其他模块                        | 修改限定在 `apps/viewer/` 和新增的 Viewer 自有包；不修改既有非 Viewer app/package、根配置和根锁文件 |
| B-06 | 原文件保持不变                        | 预览、旋转、缩放、密码读取和放映不写回用户选择或下载的原文件                                        |

## 3. 文件导入与打开流程

### 3.1 本地文件

1. 用户点击“打开文件”，选择 PPTX、PDF 或 DOCX。
2. 浏览器读取文件字节，按文件头和扩展名识别格式；超过 1 GiB 时拒绝。
3. 页面持有文件字节，生成 blob URL，并加载同源 preview iframe。
4. iframe 在浏览器内完成对应格式的解析、排版和绘制。
5. 切换文件时撤销旧 blob URL，卸载旧 iframe 及其 Worker。

空文件、类型不匹配、损坏文件、解析失败和资源缺失应有明确错误提示。密码文件按原读取能力处理；密码错误允许重试。

### 3.2 URL 导入

| 编号 | 要求                                                         | 当前状态                          |
| ---- | ------------------------------------------------------------ | --------------------------------- |
| I-01 | 输入 HTTP/HTTPS 文件直链，由浏览器下载后进入同一预览流程     | 已实现；文件服务器必须允许当前页面跨域访问 |
| I-02 | 支持签名参数、UTF-8 下载名称及无扩展名地址的内容识别         | 已实现；重定向由浏览器处理                 |
| I-03 | 下载失败、空文件或超过 1 GiB 时给出明确错误，不在服务器落盘  | 已实现                                     |
| I-04 | 不再由 Viewer 校验公网/内网地址或固定连接 IP                 | 已改为浏览器访问策略                       |
| I-05 | 不再提供内网 URL 开关                                        | 内网地址能否打开取决于浏览器和 CORS        |
| I-06 | 失败后可重新打开，再次由浏览器 fetch                         | 已实现；没有服务端会话                     |

URL 导入使用可直接下载的文件地址。普通网页和需要浏览器登录的分享页不能直接作为文件。跨域被拒绝时直接提示，不再由服务器代下载。

## 5. 界面与交互

- 文件栏统一提供文件名称、本地打开和 URL 导入；长文件名省略显示，并可查看完整名称。
- 三格式工具栏统一图标、文字标签、按钮高度、间距、选择器样式与用途分组。
- 当前适配模式、PDF 导航面板及文档信息面板应有明确选中状态；禁用、悬停、按下与键盘焦点可区分。
- PPT “开始放映”作为主要操作；页面选择继续使用原生 select。
- 适配明暗主题和窄屏换行；工具栏控件不超出窗口边界。
- PDF/Word 搜索控件默认隐藏，原搜索实现保留。隐藏时不拦截 `Ctrl/Cmd+F`；浏览器查找效果由浏览器及实际文本层决定。
- `Ctrl/Cmd+ +/-` 控制预览缩放；非输入区域的 PageUp/PageDown 用于翻页。放映快捷键沿用原组件。
- 字体回退、下载/解析失败、密码错误、跨域被拒绝及媒体不可播放应有对应提示或恢复入口。
- 链接支持 `showHeader`、`showImport`、`showUrlImport`、`showToolbar`、`showSidebar`、`showErrors` 分别控制文件栏、导入入口、文档操作栏、侧栏和错误区域；无参数时保留现有界面。`embed=1` 默认隐藏这些区域，显式开关可覆盖嵌入模式默认值。
- 主页面支持 `url` 参数自动导入 HTTP/HTTPS 文件直链；即使隐藏导入入口，也可直接展示链接指定的文档。界面选项传递到预览 iframe，隐藏仅作用于显示。

工具栏样式调整不改变文档内容 CSS、绘制比例、字体度量或原分页算法。

## 6. 文件保存在哪里

预览不把源文件写入服务器，也没有会话、心跳或 `.viewer-data`。

| 场景                         | 文件字节                                                                 |
| ---------------------------- | ------------------------------------------------------------------------ |
| 正在预览                     | 留在当前页面内存，并通过 blob URL 交给预览 iframe                       |
| 切换文件                     | 撤销上一份 blob URL，释放对应 Worker                                     |
| 关闭页面或刷新               | 浏览器释放这份内存；站点不保留可再次打开的文件副本                       |
| URL 导入失败、取消或超过上限 | 不落盘；页面只显示错误，可重新打开                                       |

原 URL 的授权期限由文件提供方决定。刷新页面后需要重新选择文件或重新导入链接。

## 7. 运行架构

页面不调用预览用的 `/api`。每次打开使用新的同源 preview iframe，隔离各格式的全局 CSS、FontFace、模块状态及浏览器 Worker。

| 部分 | 在浏览器中做什么 |
| ---- | ---------------- |
| 主页面 | 读取本地文件或 CORS 链接，识别格式，把 blob URL 传给预览页 |
| PDF | PDF.js 直接打开 blob URL；文字层、链接、已保存表单和批注沿用现有层 |
| DOCX | 解析 Worker、分页和只读视图；加密文档在浏览器解密；图片和嵌入字体从 zip 读取 |
| PPTX | 浏览器 Worker 完成打开和首轮排版；页面用已加载字体测量字宽并回传，最多 6 轮 |
| 字体 | 使用随页面发布的 Carlito、Caladea、Liberation、Noto 等度量字体，不扫描系统字体目录 |
| 媒体 | 图片、音视频从文档 zip 读出；TIFF 转成 PNG，SVG 主题色在浏览器内重着色 |

不存在编辑、保存写回、AI 或账号登录。含 HTML/MHT 的 altChunk 不会调用服务端 Chrome，页面会明确提示无法转换。字体包没有的字体会标明回退。

## 8. 构建与静态部署

本地仓库在已有开发依赖的环境下执行：

```sh
npm run dev -w @genoffice/viewer       # 静态页面，端口 11001
npm run build -w @genoffice/viewer     # 输出本 app 的 dist
npm run package -w @genoffice/viewer   # 生成独立发布目录
```

部署产物为整个 `apps/viewer/releases/genoffice-viewer/`，作为静态网站根目录。目录内是页面、预览 Worker、字体、PDF.js 资源、预生成的 `.gz`、`nginx.conf` 和许可证，不包含 Node 服务、PM2 或运行时 `package.json`。

带内容 hash 的 `/assets/` 缓存一年。`index.html` 与 `preview.html` 不长期缓存，这样新发布才会指向新的字体和脚本。nginx 对 js、css、html、json、svg、wasm、ttf 开启 gzip，并优先使用同名 `.gz`；woff2 不再压缩。

开发时 Vite 监听 `0.0.0.0:11001`，可用 `VIEWER_HOST=127.0.0.1` 限制为本机。本地文件上限 1 GiB，不代表该大小的所有格式都已完成性能验收。含 HTML/MHT 的 Word altChunk 在页面上提示无法转换。源码构建仍使用 monorepo 安装环境，静态发布运行不依赖原仓库。

## 9. 验收与后续工作

### 9.1 功能验收

- 三格式本地与 URL 导入可打开；错误、取消、密码错误和重新打开可复现。
- PPT 缩略图仅纵向滚动，翻页与原生页码选择同步；普通预览和放映中的媒体实际播放、进度推进及翻页停止可验证。
- PDF/Word 搜索控件不可见，保留实现可由回归验证；只读表单/正文不能修改原文件。
- 工具栏在明暗主题及 375/768/1130/1440 像素宽度下无控件横向溢出，键盘焦点可见。
- 验证链接开关独立生效、嵌入模式可覆盖、三格式自动导入、签名 URL 完整传递、主页面和 iframe 的错误隐藏一致。
- 发布目录可以作为静态网站根目录打开，完成 PPT/PDF/DOCX 预览。

### 9.2 原渲染一致性验收

固定原 GenOffice 提交、操作系统、字体集合、浏览器内核、viewport、DPR 和语言，建立逐页和动态播放基线。比较内容位置、换行、页数、分页、字体、表格、图片、链接、动画/转场和播放状态。

继续覆盖 PPT 复杂字体/图表/动画/媒体编码，PDF 静态填表/签名/不同批注与表单，DOCX 混合分栏/页眉页脚/脚注/修订/浮动对象/长文档/MHT。源码一致性、稳定页数和浏览器截图可证明实现沿用及当前样本可运行，不能替代原程序对照。
