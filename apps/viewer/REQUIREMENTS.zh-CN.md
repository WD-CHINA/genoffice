# Office Viewer 需求文档

版本：1.0 · 整理日期：2026-10-13。

本文汇总用户已确认的产品范围、开发边界和界面调整，并记录当前实现及待验收事项。原渲染源码基线为 `4863835963c99793c47b72473900c483e9fa0c2a`；本文整理时的代码提交为 `930ae6c1`。后续范围以用户最新确认和本文件更新为准。

“已实现”表示入口已接入并有相应功能验证，不等于所有复杂文件已通过与原 GenOffice 的逐页视觉对照。“待验收”表示仍需样本或基线证据。“待确认”表示用户尚未决定具体业务策略。

## 1. 产品目标

在现有仓库中提供独立的 Node.js 后端与浏览器前端，用于 Office 文件只读预览、PPT 放映和音视频播放。

首期支持 `.pptx`、`.pdf`、`.docx`，应用位于 `apps/viewer/`，开发、启动、构建和生产运行均可独立于其他模块进行。

还原对象是原 GenOffice 的显示和播放结果。解析、字体度量、排版、内容绘制、节点结构、内容 CSS、动画和转场继续沿用原实现；用户界面的文件栏、工具栏等宿主控件可独立调整。

## 3. 文件导入与打开流程

### 3.1 本地文件

1. 用户点击“打开文件”，选择 PPTX、PDF 或 DOCX。
2. Node 校验文件类型、内容和大小，将文件存入 Viewer 的 data 目录。
3. 服务返回随机文件 ID、名称、格式和 SHA-256，并创建预览会话。
4. 前端按格式加载独立的 preview iframe，进入对应的原渲染链路。
5. 切换文件时关闭旧会话、释放旧 iframe 与相关资源。

空文件、类型不匹配、损坏文件、解析失败和资源缺失应有明确错误提示。密码文件按原读取能力处理；密码错误允许重试。

### 3.2 URL 导入

| 编号 | 要求                                                         | 当前状态                          |
| ---- | ------------------------------------------------------------ | --------------------------------- |
| I-01 | 输入 HTTP/HTTPS 文件直链，下载后进入同一本地文件预览流程     | 已实现                            |
| I-02 | 支持签名参数、重定向、UTF-8 下载名称及无扩展名地址的内容识别 | 已实现；最多 5 次重定向           |
| I-03 | 超时、取消、超限或内容无效时清理下载临时文件                 | 已实现                            |
| I-04 | 默认仅允许公网地址，每次重定向重新校验并固定连接到已校验 IP  | 已实现                            |
| I-05 | 可信部署可显式启用内网 URL 导入                              | 已实现；配置项见第 8 节           |
| I-06 | 会话失效后可按原 URL 重新下载                                | 已实现；重新下载时原 URL 仍需有效 |

URL 导入使用可直接下载的文件地址。普通网页和需要浏览器登录的分享页不能直接作为文件；不转发用户浏览器登录凭据，不接受 URL 内嵌账号密码。HTTP 压缩响应按解码后的文档内容进行校验。

## 5. 界面与交互

- 文件栏统一提供文件名称、本地打开和 URL 导入；长文件名省略显示，并可查看完整名称。
- 三格式工具栏统一图标、文字标签、按钮高度、间距、选择器样式与用途分组。
- 当前适配模式、PDF 导航面板及文档信息面板应有明确选中状态；禁用、悬停、按下与键盘焦点可区分。
- PPT “开始放映”作为主要操作；页面选择继续使用原生 select。
- 适配明暗主题和窄屏换行；工具栏控件不超出窗口边界。
- PDF/Word 搜索控件默认隐藏，原搜索实现保留。隐藏时不拦截 `Ctrl/Cmd+F`；浏览器查找效果由浏览器及实际文本层决定。
- `Ctrl/Cmd+ +/-` 控制预览缩放；非输入区域的 PageUp/PageDown 用于翻页。放映快捷键沿用原组件。
- 字体回退、下载/解析失败、密码错误、连接中断、会话失效及媒体不可播放应有对应提示或恢复入口。

工具栏样式调整不改变文档内容 CSS、绘制比例、字体度量或原分页算法。

## 6. 会话有效期与 data 文件保留

### 6.1 当前实现规则

`VIEWER_DATA_DIR` 保存上传或 URL 下载的源文件。未配置时为构建/运行目录下 `.viewer-data`。文件以随机 ID 存储；文件记录、所有者和预览会话索引仅保存在当前 Node 进程内存中。

| 场景                       | 预览会话                                 | data 中的源文件                                        |
| -------------------------- | ---------------------------------------- | ------------------------------------------------------ |
| 正常保持预览打开           | 默认每 60 秒心跳续期                     | 随会话访问更新使用时间并继续保留                       |
| 停止请求或心跳             | 最后访问后超过默认 30 分钟，进入回收条件 | 无活动会话且文件超过 30 分钟未使用时进入删除条件       |
| 用户切换文件或显式关闭会话 | 旧会话关闭并释放 Worker/解析资源         | 不立即删除；从最后访问时间计算空闲清理                 |
| 文件上传后未创建会话       | 无预览会话                               | 从上传/下载完成时间计算空闲清理                        |
| URL 下载失败或取消         | 不创建成功文件记录                       | 删除该次未完成的下载文件                               |
| 服务重启或异常退出         | 原文件 ID、所有者与会话索引失效          | 磁盘残留文件可能继续存在；当前不会在重启后自动扫描清理 |

默认每 30 秒执行一次清理检查。TTL 使用 `VIEWER_SESSION_TTL_MS`，单位为毫秒；当前会话与文件空闲清理共用此配置。正在打开、测量或转换的会话会暂缓回收，不能将清理时间承诺为严格的秒级删除截止时间。

浏览器关闭、后台节流或设备休眠可能停止心跳，实际失效时间以服务端最后一次请求为准。原 URL 自身的授权有效期由文件提供方决定，Viewer 续期不会延长该 URL 的签名期限。

### 6.2 已识别缺口与待确认策略

**当前不能保证 data 中所有磁盘文件都按 30 分钟自动删除。** 启动时不恢复旧索引，也不扫描历史文件；进程退出前未清理的文件会成为残留文件。

后续实现前需确认：

1. data 作为临时预览缓存，还是需要成为可重复访问的长期文件存储。
2. 重启后应清理残留文件，还是恢复文件索引及访问权限。
3. 文件保留期是否继续与会话 TTL 共用，是否需要独立保留时间及最长保存期限。
4. 残留文件清理是否只作用于 Viewer 专属目录，如何保护仍在使用的文件。

这些策略尚未由用户确认，本次文档整理不修改存储行为。长期保存、重启恢复和启动扫描清理均不能作为已交付能力。

## 7. 运行架构与接口边界

浏览器负责交互与原内容展示，Node 负责文件/资源访问、会话、PPT 排版 Worker 和 DOCX 读取预处理。每次打开使用新的同源 preview iframe，隔离各格式的全局 CSS、FontFace、模块状态及浏览器 Worker。

| 接口                                             | 用途                                                            |
| ------------------------------------------------ | --------------------------------------------------------------- |
| `GET /api/health`                                | 服务状态、支持格式、Cookie 初始化、心跳间隔与 altChunk 环境能力 |
| `POST /api/files`                                | 上传文件并返回文件 ID、名称、格式与 hash                        |
| `POST /api/files/import-url`                     | URL 下载并返回同一类文件记录                                    |
| `POST /api/view-sessions`                        | 使用文件 ID 创建预览会话                                        |
| `GET /api/view-sessions/:id`                     | 查询并续期会话                                                  |
| `DELETE /api/view-sessions/:id`                  | 关闭会话与关联解析资源                                          |
| 会话内 content、字体、媒体、测量与 DOCX 解锁接口 | 为原渲染链路提供受控读取和必要排版/解密处理                     |

接口按 Cookie 所有者隔离，客户端不能指定任意服务端文件路径。媒体/文件读取支持原字节与 Range。不存在编辑、保存写回、AI 或账号登录接口。

当前是单进程内存会话实现。多实例间不共享文件索引、所有者与会话；跨实例透明访问或重启后链接恢复尚未实现，不能直接作为已有集群能力部署。

## 8. 构建与服务器部署

本地仓库在已有开发依赖的环境下执行：

```sh
npm run dev -w @genoffice/viewer       # API 3001 + Web 5180
npm run build -w @genoffice/viewer     # 输出本 app 的 dist
npm run package -w @genoffice/viewer   # 生成独立发布目录
```

部署产物为整个 `apps/viewer/releases/genoffice-viewer/`：包含 `server/`、`web/`、`assets/`、运行时 `package.json`/锁文件及许可证。发布包不携带本机 `.viewer-data`、构建审计文件或开发源码。

服务器要求 Node ≥22.12.0；在发布目录执行 `npm ci --omit=dev` 和 `npm start`。唯一外部 npm 运行依赖是锁定版本的 `playwright-core`；其余实现已打包。Node 同时提供页面、API 与受控资源，可由反向代理提供同一域名访问。

普通 PPTX、PDF、DOCX 不需要服务端浏览器；DOCX HTML/MHT altChunk 需要安装 Chrome/Chromium。部署字体及客户端浏览器/字体环境需纳入视觉验收。源码构建当前仍使用 monorepo 安装环境，独立发布运行不依赖原仓库。

| 配置                               | 当前默认与用途                                                     |
| ---------------------------------- | ------------------------------------------------------------------ |
| `VIEWER_HOST` / `VIEWER_PORT`      | `0.0.0.0` / `3001`；默认局域网可访问，`127.0.0.1` 则仅本机        |
| `VIEWER_DATA_DIR`                  | 运行目录下 `.viewer-data`；源文件目录，要求可写                    |
| `VIEWER_SESSION_TTL_MS`            | `1800000`；会话和源文件共用的空闲 TTL                              |
| `VIEWER_MAX_UPLOAD_BYTES`          | `1073741824`（1 GiB）；本地上传和 URL 下载的大小限制               |
| `VIEWER_URL_TIMEOUT_MS`            | `45000`；完整 URL 下载流程超时                                     |
| `VIEWER_URL_ALLOW_PRIVATE_NETWORK` | `false`；可信部署中可设为 `true` 允许本机/内网地址                 |
| `VIEWER_CHROME_PATH`               | 可显式指定 Chrome/Chromium 路径                                    |
| `VIEWER_FONT_DIR`                  | PPT 服务端附加字体目录                                             |
| `VIEWER_ALLOWED_ORIGINS`           | 额外允许的 Origin；默认包含本地开发 Web 地址，部署时按实际来源配置 |

当前实现的进程级上限为：64 个已登记/正在导入文件、12 个预览会话、4 个同时 URL 导入任务，altChunk 转换并发为 2。以上是代码限制，不是已完成压力测试的业务容量承诺。1 GiB 是接收上限，不代表该大小的所有格式都已完成性能验收。

## 9. 验收与后续工作

### 9.1 功能验收

- 三格式本地与 URL 导入可打开；错误、取消、密码重试、会话失效和重新打开可复现。
- PPT 缩略图仅纵向滚动，翻页与原生页码选择同步；普通预览和放映中的媒体实际播放、进度推进及翻页停止可验证。
- PDF/Word 搜索控件不可见，保留实现可由回归验证；只读表单/正文不能修改原文件。
- 工具栏在明暗主题及 375/768/1130/1440 像素宽度下无控件横向溢出，键盘焦点可见。
- 服务连续运行时验证空闲回收与文件删除；重启残留文件行为按当前限制说明，不将其判为已实现自动清理。
- 发布目录可以移到原仓库外安装运行依赖并启动，完成 PPT/PDF/DOCX 预览。

### 9.2 原渲染一致性验收

固定原 GenOffice 提交、操作系统、字体集合、浏览器内核、viewport、DPR 和语言，建立逐页和动态播放基线。比较内容位置、换行、页数、分页、字体、表格、图片、链接、动画/转场和播放状态。

继续覆盖 PPT 复杂字体/图表/动画/媒体编码，PDF 静态填表/签名/不同批注与表单，DOCX 混合分栏/页眉页脚/脚注/修订/浮动对象/长文档/MHT。源码一致性、稳定页数和浏览器截图可证明实现沿用及当前样本可运行，不能替代原程序对照。
