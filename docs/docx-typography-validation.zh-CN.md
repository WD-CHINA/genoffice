## 已处理

远程 DOCX 过去只把样式交给文字转换器，没有挂载本地阅读使用的文档级 CSS。
现在复用现有样式生成器，在首次隐藏测量之前安装样式，正文、表格、重复表头和页眉页脚共享默认字体、
字号、段落间距、行距及命名样式继承。各节的行网格和字网格设置同步用于测量与显示。
文档切换、会话恢复时撤销旧样式；页眉页脚测量缓存能够识别样式上下文变化。

原业务文件引用了主题字体，但没有主题文件。对“主题缺失、东亚默认字体无法解析”的情况，
项目使用随包的无衬线中文字体，内部别名为 `GenOffice Theme Sans SC`；默认西文字体使用 Calibri 兼容链。
中文字体文件来自既有 Noto Sans CJK SC 子集，字体高度使用该文件实际 hhea 度量（1160/-288/0，1000 units/em）。
这一规则是项目的兼容回退策略，不代表原文件含有该字体，也不等同于已取得飞书内部字体配置。
显式东亚字体和样式指定仍然优先，原始 DOCX 不被重写。

嵌入字体此前只注册了 FontFace，现在同时向排版器提供实际字体度量，常规字形优先；关闭文档时清理。
服务端样式上下文增加字体表替代信息、兼容模式、自动断词、表格行高网格及 HTML 段落间距兼容开关。
这些是可选字段，旧结构仍可读取；本机 Docker 两个实例已更新，重新下载的离线包携带相同样式数据。

## 与飞书仍有差异

对照的是此前已逐页读取的飞书 WebOffice 编辑态（5页）。CLI 静态PDF的6页不用于这次断点校准。
本轮能定位到飞书标签页，但再次自动读取超时，没有把它当作新的实时字体测量证据。

业务文件首页现在完整结束“课程常规”，第二页从热身开始，与已记录的飞书编辑态一致。
后续页仍未完全对齐：

| 位置          | 飞书编辑态记录                           | 当前Web阅读                           |
| ------------- | ---------------------------------------- | ------------------------------------- |
| 第二/三页交界 | 第三页从“稳地传到同伴脚下？”续接         | 第三页仍从指导语“去推球的中部……”续接  |
| 第四/五页交界 | 第四页已排完安全保障，并开始预计运动负荷 | 第五页仍有安全提示第4条及部分资源支持 |
| 第五页        | 完整课后小结                             | 同样到达完整课后小结和正确页码        |

当前仍采用整表连续几何切片。跨页单元格的独立续排、垂直对齐和断点选择仍需进一步对照，
不能以总页数相同宣称逐页一致。Web与Android字体和页数检查通过，也不代表两种内核的逐行像素位置完全相同。
没有添加该业务文件专属分页或强制总页数。
