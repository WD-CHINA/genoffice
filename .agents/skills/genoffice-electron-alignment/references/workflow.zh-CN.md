# 详细工作流

## 输入与模式

| 参数                  | 含义                                                         |
| --------------------- | ------------------------------------------------------------ |
| project               | 待审计/修复仓库；记录当前 HEAD、分支和已有修改               |
| release_url / version | 指定的官方 Release 和版本，不能默认使用 latest               |
| baseline              | 独立下载/解压的 Electron 基线源码；验收期间保持原样          |
| corpus                | 全部课件及其需求说明、参考截图等文件                         |
| out                   | 本次独立证据目录，不覆盖输入、基线或既有报告                 |
| mode                  | audit / repair / retest；按当前授权决定                      |
| install_policy        | forbid / allowed；与源代码修复授权分开                       |
| accepted_designs      | 问题 ID、用户原话/授权依据、适用版本与范围                   |
| coverage              | 要验收的页面、区域、组件、状态及对应端；全量和针对性复测分开 |

用户已给出的项目、版本、课件、安装/修复权限直接沿用；不重复询问。接续旧审计时复用原问题 ID 与输入别名，新增问题追加编号。仅要求整理或查看技能时，不启动业务审计。实际审计请求所需的只读下载与运行按任务范围执行；安装和源代码修复按已有授权执行，不重复申请。提交、推送或发布需要对应指令。

## 0. 下载、版本与保护

1. 确认工作区、适用规则及已有变更。输出放独立运行目录；记录当前命令、工作目录和退出码。不要回滚他人或上轮未提交修改。
2. 通过可用的 GitHub 连接、CLI 或下载工具获取**指定** Release 元数据、源码归档及需要的官方二进制。保存 URL、asset 名、下载时间、SHA256、tag 对应提交。安全解压到新目录；拒绝归档路径越界，不覆盖既有项目。默认命名 `genoffice-<version>`，实际路径写入报告。
3. 分开核对 tag/commit、源码 package 元数据、Release 应用版本和实际运行 Electron/Chromium 版本。源码元数据与发布包可能不同；保留事实及依据，不改版本字符串冒充确认。缺版本依据时标“待确认”，不凭目录名认定。
4. 在安装/构建前快照课件和基线。清点助手记录明确排除目录；有 Git 时另外保护全部已跟踪源码/资源，避免生成目录名规则漏掉受跟踪文件。下载原归档清单也可作为基线文件集。运行后复查，不只凭 `git status` 判输入未变。
5. 查看各项目锁文件、实际 runtime/包管理器、已有依赖、原启动/构建命令。允许安装时使用对应锁文件的可重复方式，记录实际解析依赖；避免混用包管理器或无意改锁。否则只列缺失及其影响。
6. 区分 pristine 源码、构建/运行副本与官方发布应用。构建会改源目录时使用独立运行副本，记录其来源和差异。profile、缓存、服务数据、日志使用本轮目录；应用可能自动保存时，使用与输入原件SHA一致的工作副本，不把修改写回原件。单独记录支持启动所需的参数调整；不改 Electron 逻辑来消除显示差异。

保护快照发现改变时，保留变更记录并标记本次基线/输入条件失效；重建可信条件后重做受影响证据。不通过重新拍快照掩盖变化，也不自动回滚用户修改。接续复测可复用经重新核实的既有下载与基线；用户明确要求重新下载时照其指令执行。

## 1. 建立“课件 / 页面 / 规则”索引

- 清点全部文件，保留路径、扩展名、大小、SHA256、输入角色。内容相同的文件保留各自路径和别名；可复用相同内容证据，但文件数、唯一内容数与实测数分别统计。
- 课件正文、需求文档和参考截图都需读取；历史截图/报告不能自动成为新的显示基线。
- 适用时读取当前可用的 PPTX/DOCX/PDF 技能或已有文档工具。不为清点擅自安装解析器。
- PPT 按 presentation 顺序定位 slide、notes、布局/母版、字体/媒体、动画/切换和隐藏状态；不要用 ZIP 文件名排序代替页面顺序。
- Word 的段落/表格/XML 块不是实际排版页。记录 section、页眉页脚、PAGE/NUMPAGES/SECTIONPAGES/TOC 字段、字体、浮动对象、OLE、媒体和加密；实际页数来自 Electron 稳定排版。
- PDF 通过可用解析器确认页数/尺寸/旋转/字体/批注/表单及加密。没有解析器则标未索引完成，不用二进制字符串正则假造页数。
- 规则记录 `rule_id → file_id → 页面/逻辑单元 → 原文件/XML/说明位置 → 显示项 → 四端验证状态`。区分课件明确规定、Electron 实测行为、课件未定义和证据不足。补齐空/错/加载等状态有依据的测试步骤，不虚构课件预期。

## 2. 定位四端实际入口

| 端       | 核对重点                                                                                                     |
| -------- | ------------------------------------------------------------------------------------------------------------ |
| Electron | 指定版本 `apps/docs`、`apps/slides`、`apps/pdf` 及相关 packages；实际打开、解析/排版/绘制、字体/媒体/错误 UI |
| Web      | 当前入口、local/server 路由、worker、样式/静态资源、字体来源、构建实际来源                                   |
| Server   | 真正 HTTP 上传→会话/构建→模型/渲染树→资源；若支持分别测模型与 server-layout，区分冷生成/缓存重放             |
| Android  | 宿主→应用/WebView→在线接口/本地回放服务→APK资源；记录设备/模拟器、WebView、渲染资源来源                      |

项目中的名称、脚本和路由可能变化。`apps/viewer/src/web/docs-remote.tsx` 等只是查找线索，应从当前入口追调用链。服务端没有独立 UI 时，评价其数据/资源导致的最终显示，并将“独立服务端界面”标不适用；这不豁免 HTTP 显示链路。

按功能列 `Electron 源实现 → 可复用核心 → 三端宿主边界 → 实际依赖/资源 → 验证入口`。主包有合适实现时优先复用；确实无法直接使用时记录查过的代码、原因和新增逻辑范围。直接复制、抽取和私有适配分别登记，不整段豁免来源守卫。

## 3. 固定可核对环境

使用同一输入 SHA256、页面/状态、语言、主题和网络条件。记录并尽量统一：

- 窗口/设备物理尺寸、CSS viewport、DPR、应用缩放、浏览器缩放、visualViewport；截图时读取实际值，不能只记 setViewport 请求值。
- Word 打印/阅读/导出预览是不同状态，先与 Electron **对应状态**比较；滚动条/scrollTop、页眉绝对定位和容器坐标分开。
- 字体请求名、实际有效字面、资源来源/SHA、样式/回退、字体加载结束；同名字体和 `document.fonts.check` 不能单独证明实际字面一致。
- 图像解码与页面排版稳定。保存原截图和采样时的 DOM/资源记录。归一化画布只作派生分析，保留比例、坐标变换和未裁切原图，避免重采样抹去差异。
- Android 固定设备/分辨率/density/方向与 WebView；不能靠桌面 UA 模拟声称真机通过。
- 冷启动、冷构建、热缓存分别记。断网测试明确断开了什么；仅移除后端 USB 映射不等于关闭所有网络。

## 4. 审计与证据

逐页面、区域、组件、状态检查布局、字体/字号/字重、颜色、间距、对齐、符号、资源、滚动、弹窗、加载/空/错、反馈和溢出。每个样本先取 Electron 证据，再判断各端；不以 Web、Server 或 Android 反定预期。

推荐组合：截图/录屏 + 实际几何/状态 + 资源/控制台。PNG 编码字节差异、透明 RGB、字体抗锯齿和 CSS 小数需分开排查；不能把“有差值”直接写成已确认可见缺陷，也不能自设百分比容差把已确认问题关闭。

记录原始测量与推断。缺少同条件证据时列“无法确认”；课件未覆盖项列“课件未定义”，有 Electron 实测时注明该比较依据。性能、接口/数据契约等只有影响显示时进入主清单；其余放附注。

原问题每端独立编号 W/S/A；跨端同根因可合并实现，但保留三端结论。按 [证据格式](evidence.zh-CN.md)填写字段。

## 5. 按授权修复

1. 确认本次明确修复范围、接受设计及既有修改。审计或复测模式不修改实现；修复已授权时继续，不另设惯例审批。
2. 以定位的 Electron 原核心为依据，连同传递依赖、字体/媒体及错误 UI 移植；解析、排版、绘制、资源管理不另造近似方案。依赖版本按实际基线核实，不锁死本次历史数字。
3. 在宿主边界处理文件/IPC/HTTP、浏览器能力、Android 内存/资源释放等。保留原尺寸/内容/错误反馈，不通过缩图、跳过尾部、掩盖失败或改期望来通过。
4. 记录源提交、路径/行、适配文件、必要性与影响。维持未改核心的精确或 token/行为一致性守卫；只登记具体必要差异。
5. 新功能、设备配置重置、生产部署等不由本工作流自动授权。只管理能确认由本轮创建的进程/端口/映射；用户已授权的正常开发运行和已有操作继续按其范围执行。

## 6. 逐端复测与收尾

- Web 本地与真实 HTTP 分测；项目支持的不同服务端排版入口也分测。用真实上传、session、units、parts/fonts 与最终页面证明接入，不只运行私有适配层单测。
- PPT 复核最终文本框、实际字体、换行和覆盖关系；静态页不代表动画/音视频同时间轴通过。
- Word 核对总块数与末尾文本、实际页数、分节/页眉页脚和目录字段；不能只数 `.pv-page` 容器。滚动后确认首/中/末页内容真正挂载并可见，重复打印/阅读切换。
- 加密文件按适用方案测正确密码、错密原表单反馈、重试、取消、再次打开；真实键盘/触摸等未测状态明确列出。
- Android 构建完成后再安装/测试。核对 APK 静态资源与目标 release 的字节、安装后 APK SHA；保留数据的正常更新按当前授权执行。在线与下载后断开后端回放分别测资源/字体/媒体。
- 跑与改动有关的测试、类型/来源/格式/定向 lint。跳过、未跑、历史失败与最终结果分开；生成产物导致根 lint 失败时如实说明，不取消规则伪装通过。
- 重启需要重新加载的本轮服务，验证冷路径和热路径；正常取消的 AbortError 不自动等于解析器崩溃，应对照完整请求时序及前端错误。
- 确认源码→构建→运行/安装件对应关系，复查保护快照，记录服务与设备状态。测试/报告生成不等于自动提交或推送。

关闭某问题必须有该端原触发状态的复测记录及当前证据。只有主根因修好但仍有确认残余时为“部分修复”；无法验证不能关闭。用户接受设计是单独状态，不记为修复通过。兼容问题保留冲突、影响、方案和各自限制。

## 本轮实践中值得复核的边界

以下是排障线索，不是默认修复或所有版本的既定缺陷：

- 文档字体/原垂直度量应在依赖其结果的表格、分段内容和分页初始化前就绪；只换 CSS 字体名不能证明度量一致。
- 流式 Word 的事务标记、原网格/行距和 row-fill 关系会影响截断及页数；用原函数和元信息回归，不添加课件专用补偿值。
- 异步 preview 可能是带 `elements` 的原模型，而绘制器要 `nodes` 树；验证契约，保持加载态直到可绘制，勿把前端取消日志当唯一根因。
- PNG 预览的字体要在实际 Canvas/worker 上下文中预备；临时大 Canvas 与最终图像的内存生命期分开。临时字体 scope 不等于主文档全局字体。
- 原导出预览的辅助页号、工具栏与普通文档视图不同；按用户指定状态选择/适配，不能因复用原组件就认定宿主显示完全一致。
- 页面按需挂载须跟踪 ready、DOM 提交、滚动和尺寸变化；页数正确但末页空白仍是显示缺陷。

## 交付

报告使用五部分：总体结论、基线与环境、按端清单、各端小结、附注。每端统计原范围、已关闭、当前差异、阻塞/非阻塞、接受设计、无法确认和课件未定义，写清计数单位。证据归属当前构建；历史 18/22、186 tests 等数字和旧问题例外不可当作新运行结论。
